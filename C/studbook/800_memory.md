# Устройство памяти программы

## Области памяти

При выполнении программы на C её память делится на четыре *основные* области.
- **Статическая память** (data на рис.).
- **Динамическая память** (heap, куча). 
- **Автоматическая память** (stack, стек).
- **Сегмент кода** (text на рис.).

&nbsp;

```
┌──────────────────┐
│      stack       │  ← Стек. Растёт вниз
├──────────────────┤
│        ↓         │
│        ↑         │
├──────────────────┤
│      heap        │  ← Куча. Растёт вверх
├──────────────────┤
│  .data / .bss    │  ← Статическая память (read-write)
├──────────────────┤
│    .rodata       │  ← read-only данные
├──────────────────┤
│      text        │  ← машинный код (тоже read-only)
└──────────────────┘
```

&nbsp;

### Статическая память 
Хранит:
  - глобальные переменные;
  - статические локальные переменные (со спецификатором `static`);
  - строковые литералы (обычно в отдельном сегменте `.rodata`, доступном только для чтения).

  ```c
  int global_var = 42;              // статическая память
  const RH = 1729;                  // статическая память или .rodata
  static int file_static = 10;      // статическая память

  float arr[1024];                  // статическая память

  void foo() {
      static int call_count = 0;    // статическая память
      call_count++;
  }
  ```

**Особенности и ограничения:**
- Время жизни — вся программа (выделяется при запуске, освобождается при завершении).
- Размер фиксирован на этапе компиляции и не меняется во время работы.
- Доступ — очень быстрый (прямая адресация).
- Размер памяти (для статических массивов) задаётся на этапе компиляции.

✅ **Плюсы:**
- Быстрый доступ.
- Не надо вручную управлять памятью.
- Нет утечек.
- Глобально доступна из любой функции.

❌ **Минусы:**
- Размер нельзя изменить во время работы.
- Память занята на всё время выполнения, даже если переменная больше не нужна.
- Загромождает пространство имён.
- Для статических массивов (на этапе компиляции) не всегда понятно, сколько памяти потребуется во время работы программы.

**Когда использовать.** Для данных, которые нужны на всём протяжении программы и размер которых известен заранее: константы; счётчики вызовов; переменные, которые нельзя сделать локальными.



### Автоматическая память (stack, стек)
Хранит:
  - адреса возврата из функций;
  - локальные (автоматические) переменные;
  - параметры функций.

  > Не стоит путать область памяти _стек_ с одноимённым типом данных и стеком процессора.

  ```c
  void bar(int param) {             // param — в стеке
      int local = 5;                // local — в стеке
      int arr[16];                  // arr (все 16 элементов) — в стеке
      const int RH = 1729;          // локальные константы тоже в стеке
  }
```

Все переменные в главной функции — это тоже локальные переменные, поэтому они тоже попадают в автоматическую память.
```c
  int main(){
      
      int local = 5;                // local — в стеке
      int arr[16];                  // arr (все 16 элементов) — в стеке
      
  }
  ```

**Особенности и ограничения:**
- Время жизни — до завершения блока (функции или составного оператора `{}`).
- Размер ограничен и обычно невелик (по умолчанию 1–8 МБ в современных системах).
- Доступ — очень быстрый (выделение — просто сдвиг указателя стека).
- Переполнение стека (stack overflow) возникает при слишком глубокой рекурсии или слишком больших локальных массивах, объявленных в стеке.

✅ **Плюсы:**
- Автоматическое управление. Память выделяется при входе в блок кода, освобождается при выходе.
- Почти нулевые накладные расходы на выделение.
- Кеш-локальность — данные расположены рядом, эффективно для кэша процессора.

❌ **Минусы:**
- Ограниченный размер — нельзя хранить большие объёмы данных.
- Время жизни привязано к блоку — нельзя вернуть локальный массив из функции.
- Рекурсия может привести к переполнению стека, т.к. туда всё время будет помещаться адрес возврата, параметры и локальные переменные.


**Когда использовать.** Для локальных переменных и массивов небольшого (известного) размера. Если массив большой (мегабайты) — лучше динамическая память.




### Динамическая память (heap, куча)
Память, выделенная функциями `malloc`, `calloc`, `realloc`. Время жизни такой памятью управляет программист — он сам решает, когда её освободить через `free`.


```c
void foo() {
    
    int *arr = (int *)malloc(1024 * sizeof(int));
    // arr — указатель в стеке
    // 1024 элемента массива — в куче
    
    // sizeof(int) — функция вычисления размера типа в байтах 

    // делаем что-то ...

    // освобождаем память
    free(arr);
}
```

После завершения функции `foo` переменная `arr` исчезает. Но память, на которую он указывает останется неосвобождённой.
При этом после потери указателя на блок памяти освободить её или обратиться к ней больше нельзя. Такая ситуация называется **утечкой памяти**. Эта память освободится только после того, как будет закрыта программа. 

Всегда освобождайте динамическую память после того, как она становится ненужной. Даже если динамическая память становится ненужной только под конец выполнения программы, её стоит освобождать. Это помогает сформировать привычку следить за динамической памятью.

**Особенности и ограничения:**
- Время жизни — с момента выделения (`malloc` / `calloc` / `realloc`) до момента освобождения (`free`).
- Размер ограничен только доступной физической/виртуальной памятью (гигабайты).
- Доступ — медленнее стека (выделение требует системного вызова или обхода списка свободных блоков).
- Требует ручного управления.каждому `malloc` должен соответствовать `free`.

✅ **Плюсы:**
- Размер ограничен только доступной памятью системы.
- Время жизни не привязано к блоку — можно передавать указатель между функциями.
- Можно менять размер через `realloc`.
- Подходит для структур, размер которых неизвестен до выполнения (массивы переменной длины, связные списки, деревья).

❌ **Минусы:**
- Требуется ручное управление — легко забыть `free`.
- Выделение медленнее, чем на стеке.
- Фрагментация памяти — после множества выделений и освобождений память может «дробиться».
- Утечки памяти и ошибки (use-after-free, double free) — частый источник багов.

**Когда использовать:** когда размер данных неизвестен на этапе компиляции, когда данные должны жить дольше вызвавшей функции, или когда объём данных велик (больше нескольких мегабайт).


### Сегмент кода (text)
Содержит скомпилированные машинные инструкции программы. Обычно доступен только для чтения.

**Особенности:**
- Размер фиксирован после компиляции.
- Попытка записи в этот сегмент приводит к **segmentation fault**.
- Туда же могут попадать строковые литералы (если они не помещены в отдельный `.rodata`).



## Что и когда использовать — сводка

| Характеристика | Статическая | Стек (автоматическая) | Куча (динамическая) |
|----------------|-------------|----------------------|---------------------|
| Время жизни | Вся программа | До конца блока | От `malloc` до `free` |
| Размер | Фиксирован (compile-time) | Маленький (1–8 МБ типично) | Большой (доступная память) |
| Скорость выделения | Мгновенно | Почти мгновенно | Относительно медленно |
| Управление | Автоматически | Автоматически | Ручное (программист) |
| Утечки | Нет | Нет | Возможны |
| Типичное применение | Константы, глобальные счётчики | Локальные переменные, небольшие массивы | Динамические структуры, большие данные |



**Access violation**, **segmentation fault** — обращение к памяти, к которой у процесса нет доступа. Типичные причины: разыменование нулевого указателя, выход за границы массива, использование уже освобождённой памяти (use-after-free).

**Стек вызовов** (call stack) — последовательность вложенных вызовов функций, которая хранится в стеке и позволяет после завершения вложенной функции вернуться в вызвавшую её.
